# Overtype — specification (0.6.2)

## Confirmed scope

Windows 11; French/English professional email and messages; a private pilot of 1–10 people. The Windows client and vLLM server are separate products, initially exercised on Lucas's PC. No voice, OCR, rich Office formatting or whole-document translation.

## Approved design

> Direction artistique « Îlot » (24 septembre 2026), livrée depuis la 0.5 et complétée en 0.6 (Réglages, accueil, serveurs, vrai verre). Plans exécutés : [DA-PLAN.md](DA-PLAN.md), [PLAN-0.6.md](PLAN-0.6.md) ; contrat courant : [BRIDGE.md](BRIDGE.md). Dépôt : BerthalonLucas/Overtype. L’ancienne conception est en fin de document (« Historique »).

Select text, press the menu shortcut: the Îlot, a small action menu, opens beside the selection. At rest it shows the last action (Enter runs it again) and a pastille for a free instruction; Tab, ↓ or hovering unfolds a 3×2 grid of tiles (by default Fix, Translate, Pro, Shorten, Email, and the free instruction while fewer than six actions exist). Letters (F T P S E), digits 1–6, Space, `/` or an unassigned letter act from the keyboard. The chosen action replaces the selected text in place. No header, oversized button or footer.

While the model works, the menu morphs into a pill (28 px high, 44 px wide) carrying the Perle orb, shown after 250 ms; no text, and the pill never grows. Where the application exposes its selection through UI Automation, a light sweep is drawn over the selected lines by a separate, never clickable window (`halo`); Overtype never recolours the source's letters. After the paste: a traced check, an Undo button with an 8 s countdown (paused on hover), and the changed words highlighted, independently of Undo, until the user's next action in the text and at most `afterReplace.changedWordsSeconds` (60 s by default, 5 to 120 s in Settings); the pill moves under the new text and never covers it. Each of these can be switched off in Settings. Errors are classified: a configuration error (address, key, model, rights) offers a button that opens the exact Settings field; a transient error offers Retry; a refused paste or a changed selection replaces nothing and offers the result to copy.

The theme follows Windows: light glass in light mode, dark glass in dark mode. The default material is the real glass (`glassMaterial: 'glass'`): Windows' compositor blurs what lies behind each floating surface (`src-tauri/src/backdrop.rs`); the painted glass is the fallback where Windows cannot draw it, and a hidden setting. Icons: Lucide, stroke 1.5. A fresh install speaks the language of Windows when it is French, English otherwise; a complete toggle lives in Settings › General. Motion uses Apple's « smooth » spring preset (« bouncy » as an option); content stays centred while a surface changes shape. A setting « Animations: follow Windows / always / reduced » replaces the implicit OS preference; reduced keeps only short opacity fades, a still orb and a still veil instead of the sweep.

The « Show result » mode (no replacement) and long translations keep their behaviour (short glass near the selection, reading band at the bottom of the cursor's screen), restyled in the new material, icons and motion (plan, lot 11). Idle means hidden except the tray icon. Settings follow the same theme at a readable normal window size and accept direct links from errors to a field.

Use Motion/Radix/Lucide for accessible interactions. The overlay window is reserved once for the largest form; inside it the DOM animates the surface's width, height and radius, and no native resize (`SetWindowPos`) happens during an animation (plan §4.3). Native hit-testing must follow the actual surfaces; transparent margins must not intercept desktop clicks. Closing cancels immediately and permits a short bounded exit animation, with a native fallback if the frontend does not acknowledge. The lab and mockups do not establish native blur, focus behaviour or performance.

## Interaction

Ctrl+Alt+Space (setting string `Ctrl+Alt+Space`), configurable, opens the Îlot. No Ctrl+Alt+letter combination is offered by default: Ctrl+Alt is AltGr on AZERTY, and the shortcut recorder flags combinations that collide with AltGr on the active layout. A binding targets either the menu or one action directly. Pressing the menu shortcut twice within 400 ms reruns the last action, remembered per source application (process name → action id, never text). Capture: read the selection via UI Automation, with the rectangle of every selected line; else copy it for the user (synthetic Ctrl+Insert once the chord is released, clipboard restored); else accept a copy the user made less than three seconds before; else a short notice, never a modal dialog. Without selection rectangles nothing is drawn over the text and the pill alone opens at the bottom of the cursor's screen. Selection coordinates determine placement; clamp to the monitor working area and flip above when needed. The overlay takes keyboard focus only while the menu is open and gives it back to the source before pasting; afterwards it never activates, so clicking Undo does not steal focus. Escape in the menu closes it and returns focus to the source without pasting; later, Escape dismisses/cancels. Scroll/window/selection changes invalidate replacement and stale anchoring. Result actions become active only after a complete response. Never paste into an unverified or changed target. Undo sends Ctrl+Z to the source by default, only after revalidating that the source is in the foreground and the pasted text is still in place, and disappears as soon as the user types in the source; the alternative (reselect the new text and paste the original back, same revalidation) is a setting. Clipboard restoration must not overwrite newer user content.

## Client and server

Tauri 2 + React/TypeScript; Rust owns native capture, windows, network, storage and secrets. React communicates only through the typed bridge. Browser preview provides deterministic mock responses and is clearly identified as a demo. Real desktop mode is the default for the packaged app.

Since 0.6 the client knows servers, not modes or profiles: 1 to 8 OpenAI-compatible servers (address without `/v1`, key or none, model), one of them the default, no implicit fallback between them. The delivered server (`server/`): vLLM 0.28.0 stable, pinned image and model revisions; fast: tencent/Hy-MT2-1.8B BF16, quality: tencent/Hy-MT2-7B-FP8. OpenAI /v1/models and /v1/chat/completions with streaming. The delivered profiles serve an 8192-token context. The client sends at most 200,000 characters and, since 0.6.1, no `max_tokens`; it rejects incomplete generations (`finish_reason: length`, a broken stream) explicitly. Official templates and generation parameters must be recorded. These remain candidates pending actual GPU and quality measurements. Since 0.4.0 the delivered server also has a `general` profile (Gemma 4 12B QAT with speculative decoding) for correcting and rewriting: the Hy-MT models only translate (README.md).

Defaults: interface in the language of Windows (French, else English), menu on Ctrl+Alt+Space, theme following Windows, « smooth » motion, Perle indicator, real glass, no autostart, history off. The French target is no longer a default: since 0.4.0 the language lives in each action's instruction. Optional local history: Windows DPAPI, 7 days/100 entries, delete individual/all. No content logging. HTTP is accepted for any host; to another machine the interface warns « Unencrypted connection », and HTTPS is recommended. Credentials remain on the machine.

## Delivery and evidence

First milestone: native Tauri visual prototype and simulated responses. Then real inference integration. Test cancellation, stale streams, clipboard races, focus/selection changes and network failures. Test Edge/Chrome/Word/Outlook/Teams manually; track unrun cases honestly. Design checks at 100/125/150/200% scaling and reduced motion. Evaluate 100 balanced FR/EN excerpts, fidelity/names/numbers/format and latency p50/p95 at 1/4/10 concurrent requests. Do not fabricate model results or human scores. Package Windows installer, separate reproducible server and rollback instructions.

All code/config/docs/test data and selected design references are versioned in GitHub repo BerthalonLucas/Overtype. Never commit confidential examples, model weights or secrets.
