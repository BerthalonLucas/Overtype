# Comparaison critique de l’audit Claude — Overtype main 0.6.2

## Verdict

L’audit tiers apporte une **bonne cartographie de dette et de documentation**, pas une raison de réécrire la stack. Ses observations de duplication sont souvent vraies ; ses conclusions « à virer / remplacer » doivent être séparées de leur preuve et des contraintes produit. **Aucun vote entre agents** : les convergences ci-dessous renvoient aux chemins et aux résultats vérifiés, non au nombre de rapports concordants.

- **À conserver comme compléments ciblés :** journal du setup sans primitive modale (R9), Tooltip Provider isolé (R11), deux contrôleurs d’essai aux politiques différentes (D2), fonction production dans mock (D3), simplifications de l’API Tauri (R6), fixtures Playwright répétées (R12), features/déclarations explicites (S2/S6/S13).
- **Convergences déjà couvertes :** persistance setup/réglages (FE-05), erreurs IPC/i18n (ARCH-05), ACL métier (SEC-03/NATIVE-011), commandes synchrones/locks (NATIVE-005), monolithe d’orchestration (ARCH-04), parsing .env/SSE Python (ARCH-01/02), portabilité labo (DEP-004/ARCH-06), gate release (QA-02), documentation HTTP (SEC-04).
- **À rejeter comme conclusions générales :** deux moteurs de mouvement runtime (D10), tokens différents forcément sans frontière (D8), HeroUI forcément mort après choix Radix de production (M12), trois projets/locks exigeant des workspaces (H9), valeurs persistées FR/EN constituant un défaut (C8).
- **Ne pas déprioriser nos risques natifs au profit des statistiques de style.** Le tiers mentionne revalidation/restauration comme points sains, mais ne réfute pas les chemins fail-open UIA, copie sans provenance, perte de formats et injection partielle de notre audit. Sa lecture partielle et l’absence d’essais Windows sont déclarées. La simple présence de trois contrôles ne prouve pas qu’ils refusent tous les cas incertains.

## Arbitrages majeurs : réinvention, frameworks, versions

### Motion et CSS : pas deux moteurs ni un second framework runtime

`src/motion/surface.ts:26,44` appelle **Motion.animate** ; `spring.ts:55-57` convertit Apple duration/bounce en **visualDuration**. `tokens.ts:10-12` précise que CSS est précalculé et que rien n’est échantillonné au runtime. Le solveur/générateur sert tests/génération CSS et simulation du labo, pas remplacement de Motion dans le produit. `components/motion.ts:3-6,27-34` est un autre adaptateur de tokens du même Motion. Les paramètres `duration` et `visualDuration` ne sont pas interchangeables : remplacer mécaniquement l’un par l’autre changerait les courbes.

`components/base.css:1-10` explicite matière mate de fenêtres et flottante, namespace `--ft-*` pour ne pas toucher overlay ; `theme.css:1-10` décrit flottants et fallback. Une recette commune ou un gradient copié peut être dette ; couleurs/préfixes/rayons différents ne prouvent pas une réinvention. Garder frontière produit et mutualiser des invariants, non forcer un kit unique partout.

### Labo : prototype, référence et runtime distincts

`AGENTS.md:8-9` demande de **garder** les labos comme références. `reglages/README.md:3-9` décrit comparaison de bases/matières/primitives. `build.mjs:26-41` résout les imports externes vers les dépendances du labo pour éviter deux copies React dans sa page. HeroUI/Tailwind/React Aria ne sont pas des frameworks doublés dans le bundle de l’app.

D23 garde un fond de vérité : `Demo.jsx` possède `IlotLayer/HaloLayer` et timeline propre. Mais `src/demo/app.js:19-30` importe métriques, ressorts, géométrie, diff et CSS **réels** ; « copie à la main de toute l’app » est excessif. La démo runtime `src/demo/Demo.tsx:10-22` réutilise directement IlotView/HaloView/resultContent. Corriger dérive ou extraire rendu pur ; ne pas supprimer référence/prototype sur seule étiquette duplication.

### Win32 : réutiliser bindings, préserver transactions métier

R1 concorde déjà avec notre revue native : utiliser signatures `windows` existantes réduit ABI manuelle mais ne fournit pas provenance/ownership/rollback de presse-papiers. **GlobalFree appartient à Foundation**, pas Memory dans la version exacte0.62.2. R2 est un complément concret : GetUserDefaultUILanguage et GetSystemPowerStatus existent, moyennant features Globalization/Power. `host.rs:98-107` concerne en revanche SetWindowCompositionAttribute : ne pas inclure cette API non documentée dans une promesse de remplacement complet.

R4 reste expérimentation : `system_theme.rs:1-4` documente divergence du media query dans fenêtre empaquetée. Tauri theme/onThemeChanged mérite comparaison native, pas suppression immédiate. R5 reste option : `replace_file` emploie **MOVEFILE_WRITE_THROUGH** ; `std::fs::rename` + sync_all doit être requalifié sur remplacement/durabilité, pas supposé équivalent parce que diagnostics utilise rename.

### Versions : pas de politique latest

Tauri API/CLI/crates n’exigent pas numéros identiques ; updater~2.12 est compatible Tauri2.11.5. Les piles Windows0.61/0.62 et reqwest native-tls/rustls proviennent de chaînes différentes. `browser_keys.rs:1-8` justifie vtable surtout par API Tauri non exposée : upgrade2.12 n’est pas preuve qu’elle devient inutile.

Actionsv7 existent via API officielle ; node20 est retiré, **runners migrent par défaut node24** : les tags anciens ne prouvent pas CI cassée. Notre durcissement SHA des Actions conserve priorité. jsdom/happy-dom/Vitest browser nécessitent qualification des sémantiques et du coût, pas échange basé sur nombre de majeures. cmdk sans release récente n’est pas preuve abandon. Pour vLLM0.28, notre DEP-001 fournit des advisories et conditions réelles ; calendrier V1 tiers non revalidé ici. Préserver recette WSL2 et certificats d’entreprise avant migration.
